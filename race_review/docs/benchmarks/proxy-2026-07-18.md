# Proxy benchmark: GTX 1070

Date: 2026-07-18

## Scope

This is a bounded host verification, not a full-chapter benchmark. Both production proxy
profiles encoded the same 30-second window beginning at 180 seconds in `GX020115.MP4`.
The window includes fast asphalt texture, track edges, distant signage, and another car.

- Source: 3840x2160 HEVC at 60000/1001 fps, 534.534 seconds, 4,006,805,630 bytes
- Host: NVIDIA GeForce GTX 1070, 8 GiB
- Driver/CUDA: 560.35.03 / 12.6
- FFmpeg: Ubuntu 4.4.2
- CPU profile: x264 veryfast, CRF 21
- CUDA profile: NVDEC and `scale_cuda`, NVENC p4 HQ VBR, CQ 21
- Both outputs: 1920x1080 at 60000/1001 fps, two-second GOP, AAC 160 kbps

## Results

| Backend | Wall time | Final FFmpeg speed | Size | Average bitrate | Seek at 5 s | Seek at 17 s |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| CPU | 30.42 s | 0.99x | 118,572,768 B | 31.57 Mb/s | 0.21 s | 0.17 s |
| CUDA | 10.69 s | 2.89x | 153,825,967 B | 40.93 Mb/s | 0.24 s | 0.23 s |

On this window CUDA was 2.85 times faster and produced a 29.7% larger file. The short
window is sufficient to confirm the host path but must not be presented as a measured
full-chapter completion time or output size.

## Quality check

Frames at source time 187 seconds were extracted from the source and both proxies. At
normal size there was no obvious additional loss from NVENC in the asphalt texture,
painted and concrete track edges, car contour, or distant signs. The CPU and CUDA frames
measured SSIM 0.931 and PSNR 34.16 dB against each other. Source-relative single-frame
metrics were nearly equal but are timing-sensitive on this moving scene, so they were not
used to tune the encoder.

Decision: keep NVENC CQ 21 and preset p4 unchanged. The speed gain is useful, seek latency
remains comparable, and the larger proxy is acceptable pending broader product work.

## Host-path finding

The initial forced CUDA run failed before decoding because FFmpeg 4.4 does not support
`-fps_mode`. The proxy command now uses the equivalent `-vsync cfr`, which works on the
documented host. The rerun completed with hardware HEVC decode, CUDA scaling, and NVENC
H.264 encoding; this confirms the GPU path by execution rather than encoder listings.

## Remaining work

A full 534.534-second CPU/CUDA chapter benchmark was intentionally not run. It would add
little confidence beyond this host verification while consuming substantial time and
several gigabytes. Run it only if future proxy tuning needs chapter-wide size or thermal
behavior.
